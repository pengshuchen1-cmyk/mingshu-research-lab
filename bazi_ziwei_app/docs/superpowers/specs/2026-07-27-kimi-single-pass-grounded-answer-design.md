# Kimi 单次生成与本地证据装配设计

## 背景与目标

当前 Kimi K3 问答存在两个相互叠加的问题：

1. Kimi 生成长篇、严格 JSON Schema 回答时，单次响应经常超过 60 秒；SDK 自动重试一次后，客户等待约 120 秒。
2. 云端回答返回后，本地校验要求 `chart_evidence` 和 `rule_evidence` 与本地文本逐字映射。Kimi 对证据进行正常改写也会被拒绝，随后编排器再次请求整篇回答，使总等待时间达到约 180 秒。

本次调整的目标是：保持本地“四柱八字分析规则”为唯一事实来源，同时让 Kimi 只承担问题理解、连续追问和自然语言分析；每次客户提问最多发起一次云端生成，不再因为证据措辞差异重写整篇回答。

## 方案选择

采用方案一：本地证据装配、云端正文生成、单次调用。

未采用的方案：

- 仅放宽现有模糊文本匹配：改动较小，但仍让模型重复生成本地已经拥有的证据，并保留双重调用风险。
- 保留纠错重试并提高超时时间：可以减少部分超时，却会继续产生 120—180 秒等待，无法解决结构性问题。

## 架构边界

### 本地规则负责

- 四柱、日主、强弱、格局、十神、喜忌、大运、流年等事实；
- 与当前问题相关的命盘证据；
- 与当前问题相关的规则原文和稳定规则编号；
- 对云端自然正文中的明确事实、绝对化承诺、婚姻现实状态断言进行校验；
- 云端不可用或正文校验失败时生成本地完整回答。

### Kimi 负责

- 理解客户问题及最近的去身份化对话；
- 依据请求内提供的事实和规则组织自然分析正文；
- 按单点、专题、长周期问题自适应展开；
- 给出条件分支、现实建议和必要限制。

Kimi 不再生成供机器使用的命盘证据列表和规则证据列表，也不得重新排盘或覆盖本地结论。

## 数据流

1. 本地从当前命盘构造去身份化 `AIRequestContext`。
2. 本地同步选出问题相关的命盘证据、规则证据及规则编号。
3. Kimi 接收相同的命盘事实和规则材料，但只返回自然分析正文。
4. 本地校验正文中可机器识别的事实与安全边界。
5. 校验通过后，本地把准确的命盘证据、规则证据、时间条件和限制装配进最终答案对象。
6. 校验失败或服务异常时立即进入本地完整降级，不再次调用 Kimi。

页面继续自然展示正文，不强制显示固定六栏目；本地装配的证据保留在“机器校验明细”中，供用户按需展开。

## 调用与等待边界

- Kimi SDK `max_retries=0`，避免一次请求被自动复制。
- 编排器每次客户提问最多调用云端一次。
- 使用 90 秒单次请求等待上限，覆盖实测约 64 秒的正常 K3 专题生成，同时保证用户总等待不会因隐藏重试扩大到 120—180 秒。
- 保持 `reasoning_effort=low`。
- 云端仍使用非流式返回；只有完整正文通过本地校验后才展示，避免将未校验事实提前输出。

## 校验策略

继续拒绝：

- 与四柱、日主、性别、强弱、格局、喜忌、十神、大运和时间事实冲突的明确陈述；
- 未提供或未经授权的干支事实；
- 保证发财、保证结婚、必然离婚等确定性承诺；
- 将八字判断冒充现实婚姻登记状态。

取消：

- 对 Kimi 生成的 `chart_evidence`、`rule_evidence` 做逐字映射，因为这些字段不再由 Kimi 生成。

最终证据由本地上下文原样装配，因此无需依赖模型复述是否精确。

## 错误处理

- 超时、认证、额度、限流、网络和服务异常：立即使用对应原因降级。
- 云端结构无法解析或正文违反事实边界：立即标记格式或本地校验失败并降级。
- 不执行云端纠错重试。
- 页面保留现有明确降级提示，客户能区分云端验证回答与本地完整回答。

## 测试与验收

自动化测试必须证明：

1. SDK 构造时不启用自动重试。
2. 无论格式异常或本地校验失败，编排器每个问题只调用云端一次。
3. Kimi 客户端只要求自然分析正文；证据字段由本地装配。
4. Kimi 对规则进行自然语言改写不会因为证据逐字不一致而被拒绝。
5. 云端正文若把“身弱”写成“身强”等真实事实冲突，仍会被拒绝。
6. 1999 命例和原有五个真实命例的排盘、隐私和问答验收保持通过。
7. 全量测试通过后重启本地网页，再执行一次真实 Kimi 专题问答，记录总耗时、来源和是否降级。

## 非目标

- 不修改排盘算法和本地“四柱八字分析规则”。
- 不把真实命例写入生产规则或提示词。
- 不改用其他模型。
- 不把未经校验的流式片段直接展示给客户。
