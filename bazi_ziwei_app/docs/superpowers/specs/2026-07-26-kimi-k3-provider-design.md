# Kimi K3 云端问答接入设计

日期：2026-07-26

## 目标

将“命数研究室”的云端问答服务接入 Kimi K3，同时保持本地“四柱八字分析规则”为排盘、命盘事实和回答校验的唯一规范来源。

本设计替代既有设计中“云端与本地回答每次固定展示六个板块”的要求。回答改为根据客户问题自然组织，不再为了格式机械补齐无关栏目。

## 已确认边界

- 默认云端服务商为 Kimi。
- 默认模型为 `kimi-k3`。
- 国内服务地址为 `https://api.moonshot.cn/v1`。
- 本机通过 `.streamlit/secrets.toml` 保存 API Key。
- 正式部署通过服务器环境变量保存 API Key。
- 服务器环境变量优先于本机 Streamlit secrets。
- API Key 不得显示在页面、日志、测试报告或版本库中。
- 现有 OpenAI 客户端暂时保留，但默认不启用。
- 不修改排盘、历法转换、强弱、格局、财运、事业、姻缘和流年规则。

## 方案选择

采用“服务商适配层”方案。

问答编排器不再直接构造 OpenAI 客户端，而是通过统一的云端问答接口选择 Kimi 或现有 OpenAI 适配器。Kimi 是默认服务商，后续如需切回 OpenAI，只需修改服务器配置，不需要再次改动八字规则或页面业务逻辑。

不采用以下方案：

- 直接覆盖现有 OpenAI 客户端：改动虽少，但会丢失服务商切换能力。
- 建设任意 OpenAI 兼容平台的通用网关：当前需求只有 Kimi，通用网关会增加无必要的配置、错误分支和测试范围。

## 组件设计

### 配置读取

`AIConfig` 增加服务商和服务地址配置，并按以下优先级读取：

1. 服务器环境变量。
2. `.streamlit/secrets.toml`。
3. 安全默认值。

配置项包括：

- `MINGSHU_AI_PROVIDER=kimi`
- `MOONSHOT_API_KEY`
- `MINGSHU_AI_MODEL=kimi-k3`
- `MINGSHU_AI_BASE_URL=https://api.moonshot.cn/v1`
- `MINGSHU_AI_REASONING=high`
- `MINGSHU_AI_TIMEOUT_SECONDS`

未配置服务商时默认选择 Kimi。未配置密钥时不得发起云端请求，直接进入现有本地完整降级路径。

Kimi K3 的推理强度只允许 `low`、`high`、`max`，默认使用 `high`。为兼容旧配置，读取到 `medium` 时映射为 `high`，其他非法值回退为 `high`。

项目只提交 `.streamlit/secrets.toml.example` 示例文件；真实 `.streamlit/secrets.toml` 必须被 Git 忽略。

### Kimi 适配器

新增独立 Kimi 客户端，使用 Kimi 兼容的 OpenAI Chat Completions 接口：

- `base_url=https://api.moonshot.cn/v1`
- `model=kimi-k3`
- 非流式请求
- 使用 `response_format={"type": "json_schema"}` 约束内部响应
- 从 `choices[0].message.content` 读取并解析结果

内部结构化输出只用于可靠解析和本地规则校验，不等于网页固定展示结构。

### 服务商选择

新增客户端工厂，根据 `MINGSHU_AI_PROVIDER` 返回对应适配器：

- `kimi` → Kimi K3 客户端
- `openai` → 现有 OpenAI 客户端

未知服务商视为配置异常，不尝试调用外部服务，进入本地降级并记录安全的错误类别。

### 问题自适应回答

云端回答根据问题范围决定内容和篇幅：

- 简单问题直接回答结论、关键依据和必要建议。
- 财运、事业、姻缘、原生家庭、流年等复杂问题自然分段并提供多层分析。
- 涉及年份或月份时增加阶段、触发条件和注意事项。
- 涉及婚姻登记状态时，先说明八字不能确认现实登记事实，再给出概率倾向。
- 现实建议、限制和风险只在与问题相关时出现。

前台不再固定显示“分析结论、命盘依据、规则依据、阶段与触发条件、现实建议、不确定性与限制”六个栏目。

内部返回协议使用一个必填的自然语言主回答，以及可选的命盘证据、规则证据、时间条件、建议和限制列表。主回答不能为空；可选列表可以为空。页面直接展示主回答，只在需要时折叠展示非空的校验材料。

### 本地事实边界

发送给 Kimi 的内容继续限制为：

- 去身份化的规范命盘事实。
- 与问题相关的本地四柱规则证据。
- 清理后的客户问题。
- 最近最多六条清理后的对话消息。

不得发送：

- 姓名。
- 原始出生日期和时间。
- 出生地点、经纬度。
- API Key。
- 档案编号、日志、数据库内容。

Kimi 不得重新排四柱、修改强弱、格局、喜忌或编造当前现实状态。所有命盘事实仍由本地规则生成，并由现有回答校验器校验。

## 数据流

```text
客户问题
  → 本地规范 ChartFacts 与相关规则
  → 隐私清理
  → 云端客户端工厂
  → Kimi K3 Chat Completions
  → 内部结构化解析
  → 本地事实与边界校验
  → 问题自适应自然回答

密钥、余额、网络、格式或校验异常
  → 本地四柱规则完整回答
  → 页面显示明确降级原因
```

## 错误与降级

沿用现有安全错误分类：

- 未配置 API Key。
- 余额或额度不足。
- API Key 无效或无权限。
- 触发速率限制。
- 网络错误。
- 请求超时。
- 服务不可用。
- 响应无法解析。
- 云端回答未通过本地规则校验。

只有 Kimi 明确返回余额或额度错误时，页面才能显示“余额或额度不足”。其他无法确定的错误显示为网络或服务异常。

未知服务商配置不发起外部请求，按“服务不可用”安全降级。

云端失败后仍返回本地完整回答，同时明确提醒本次回答可能不如云端全面。错误信息不得包含原始供应商响应、密钥、问题原文或个人出生资料。

## 测试与验收

### 配置

- 环境变量优先于 Streamlit secrets。
- 本机 secrets 在没有环境变量时生效。
- 缺少密钥时不初始化云端客户端。
- 默认服务商和模型分别为 `kimi`、`kimi-k3`。
- 未知服务商安全降级。
- 真实 secrets 文件不会被 Git 跟踪。

### Kimi 客户端

- 请求发送至 `https://api.moonshot.cn/v1/chat/completions`。
- 使用 `kimi-k3`。
- 请求中只包含去身份化事实和近期清理后的上下文。
- 有效结构化响应能转换为内部回答对象。
- 401、403、429、网络错误、超时、服务端异常和格式异常正确分类。
- 原始错误信息和密钥不会向页面泄露。

### 回答呈现

- 简单问题不强制显示六个固定栏目。
- 复杂问题仍能输出与问题匹配的多层次详细分析。
- 不显示空栏目或为了格式生成的重复内容。
- 婚姻现实状态使用概率倾向而非确定事实。
- 云端回答改变本地命盘事实时被校验器拒绝。

### 真实命例

使用以下六例进行回归：

1. 农历 1986 年七月初十上午 10 点左右，女。
2. 农历 1977 年九月二十九晚上 7 点半，男。
3. 农历 1974 年六月十七下午 1 点至 3 点左右，男。
4. 公历 1994 年 9 月 23 日酉时，男。
5. 公历 1996 年 9 月 4 日 23:45，女。
6. 农历 1999 年七月初一巳时，男；转换为公历 1999-08-11 10:00，四柱为己卯、壬申、乙未、辛巳。

六例验证排盘不变、上下文去身份化、Kimi 回答可解析、本地事实校验有效、回答结构随问题变化，以及云端中断时的本地降级。

## 完成标准

- 本机可通过 Streamlit secrets 安全调用 Kimi K3。
- 正式部署可通过服务器环境变量调用 Kimi K3。
- 网页不再提示“未配置 AI 服务”，且回答来源显示为云端 AI 分析。
- 简单问答简洁直接，复杂问答保持多层次分析，不固定六段。
- 本地四柱事实、规则和校验边界不被改变。
- 云端异常提示准确，本地完整降级仍可用。
- 六个真实命例和完整自动化测试全部通过。
