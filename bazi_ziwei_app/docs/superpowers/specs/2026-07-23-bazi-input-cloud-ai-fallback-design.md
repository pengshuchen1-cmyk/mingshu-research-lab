# 农历输入与云端优先八字问答设计

日期：2026-07-23

## 目标

同时解决两个用户可见问题：

1. 农历生日输入容易被误当成公历，导致客户得到与预期不同的命盘。
2. 当前未配置 API Key 时，AI 问答退回一段式本地摘要，详细度明显低于任务栏中的连续分析。

最终系统仍以本地“四柱八字分析规则”为唯一排盘与命盘事实来源。云端 AI 负责理解问题、连续追问、分析推理和语言组织；云端不可用时，本地规则提供完整答案骨架，并明确展示降级原因。

## 验收基准

新增真实验收命例：

- 输入：农历 1999 年七月初一，非闰月，男，巳时（10:00）
- 转换：公历 1999-08-11 10:00
- 四柱：己卯、壬申、乙未、辛巳

“乙卯”不是该年份的正确年柱。1999 年立春后年柱按本地规则与独立历法转换均为“己卯”。

除该命例外，继续保留原有 U01–U05 五个真实命例作为回归验收集。

## 权威边界

### 本地规则负责

- 公历与农历转换
- 立春换年、节令换月、23:00 换日
- 五虎遁、五鼠遁
- 年柱、月柱、日柱、时柱
- 起运方向与起运时间
- 日主强弱、格局、喜忌
- 财运、事业、姻缘等规范命盘事实
- 云端回答的事实一致性校验

### 云端 AI 负责

- 理解客户的具体问题
- 使用完整规范命盘事实和规则依据进行分析
- 组织多层次回答
- 理解连续追问和近期对话语境
- 在不改变本地事实的前提下解释财运、事业、姻缘、家庭与时运

云端不得依据原始出生资料重新排四柱，也不得覆盖本地计算出的强弱、格局或规则结论。

## 农历输入设计

### 历法模式

“公历 / 农历”切换放在延迟提交表单之外，使切换后页面立即显示对应输入控件，避免 Streamlit 表单不重绘条件字段。

### 公历输入

公历继续使用明确标注为“公历出生日期”的日期控件。

### 农历输入

农历不再使用看起来像公历日历的日期选择器，改为独立字段：

- 农历年份
- 农历月份（一月至十二月）
- 农历日期（初一至三十）
- 是否闰月
- 时间精度：精确时间 / 传统时辰 / 时辰不详
- 精确时间：小时、分钟
- 传统时辰：子、丑、寅、卯、辰、巳、午、未、申、酉、戌、亥

传统时辰映射到该时辰的标准代表时间。子时必须进一步区分“23:00–23:59”和“00:00–00:59”，因为本项目在 23:00 换日。

### 两步确认

第一步点击“校验并预览”，系统只进行输入校验、历法转换与四柱计算，不建立正式会话命盘。

校验成功后固定显示转换回执：

```text
原始输入：农历1999年七月初一，非闰月，男，巳时
标准时间：中国标准时间 1999-08-11 10:00
四柱预览：己卯 / 壬申 / 乙未 / 辛巳
计算依据：立春换年、节令换月、23:00换日、五虎遁、五鼠遁
```

客户点击“确认生成命盘”后，系统使用同一份已校验输入重新构造正式命盘；预览与正式结果的四柱指纹必须相同，否则阻止生成并提示重新校验。

闰月无效、农历日期不存在、时间不完整或转换失败时，不显示确认按钮，只显示明确错误。

## 云端优先问答设计

### 正常路径

1. 本地规则生成并附加规范 `ChartFacts`。
2. 系统对用户问题和近期对话做隐私清理，但保留具体诉求、目标年份、行业、借贷、婚姻状态等语义。
3. 向云端发送完整规范命盘事实、相关本地规则、清理后的具体问题和近期真实问答内容。
4. 云端使用结构化响应返回固定板块。
5. 本地校验四柱、强弱、格局、财运/姻缘星体归属、时间事实和禁止保证性表述。
6. 首次不合格时携带具体违规项纠正重试一次。
7. 第二次仍不合格时切换本地完整回答，并显示“未通过本地规则校验”的降级提示。

系统默认使用配置的云端 AI。只要 API 可用，回答理解、推理、组织和连续追问都由云端完成。

### 云端上下文

当前只把问题压缩成“问题类别：财运”等标签，且把历史压缩成“此前询问过财运”，这是回答通用化的直接原因之一。

修改后上下文包含：

- 四柱、藏干、十神、五行数量
- 强弱结论、喜忌与完整证据
- 格局结论与完整证据
- 财运、事业、姻缘规范事实
- 起运、大运、当前年月日干支和明确目标年份
- 相关本地规则文本
- 清理后的具体用户问题
- 最近最多六轮清理后的真实问答内容

姓名、精确出生日期、出生地点、API Key、日志和其他身份信息不得发送。页面隐私说明必须明确告知：AI 问答会向配置的云端服务发送去身份化命盘事实、问题和近期对话。

### 固定回答结构

云端与本地降级回答统一使用以下结构：

1. 分析结论
2. 命盘依据
3. 规则依据
4. 阶段与触发条件
5. 现实建议
6. 不确定性与限制

回答必须针对当前命盘引用具体事实，不能只输出通用性描述。

## 本地完整降级回答

本地降级回答不是当前的一段式摘要，而是根据问题类别组合 `ChartFacts`、证据、规则和本地专项分析，生成与云端相同的六段结构。

本地降级适用于：

- 未配置 API Key
- API 余额或额度不足
- API Key 无效或无权限
- 网络错误、超时或服务异常
- 云端结构化响应无法解析
- 云端回答连续两次未通过本地规则校验

本地回答仍需尽量覆盖客户问题，但页面必须明确说明其详细度可能不及云端。

## 降级提示与错误分类

系统不得把所有 API 异常统一为 `service_error`。在不泄露密钥或供应商内部信息的前提下，至少区分：

- `missing_api_key`
- `insufficient_quota`
- `invalid_credentials`
- `rate_limited`
- `network_error`
- `timeout`
- `service_unavailable`
- `unparseable_response`
- `local_validation_failed`

页面提示分别为：

```text
未配置 AI 服务，当前已切换为本地四柱规则完整分析。回答可能不及云端全面，请配置 API Key 后重试。
```

```text
AI 服务余额或额度不足，当前已切换为本地四柱规则完整分析。回答可能不够全面，请充值后重试。
```

```text
网络或 AI 服务出现短暂异常，当前已切换为本地四柱规则完整分析。回答可能不够全面，请稍后重试。
```

```text
本次云端回答未通过本地四柱规则校验，当前已切换为本地完整分析，请稍后重试。
```

只有供应商明确返回额度或计费错误时才能显示“余额或额度不足”；无法判定时使用网络或服务异常提示，避免误报。

回答来源固定显示为以下之一：

- `云端 AI 分析 · 本地规则校验`
- `本地完整分析 · 云端服务未配置`
- `本地完整分析 · 云端额度不足`
- `本地完整分析 · 网络或服务异常`
- `本地完整分析 · 云端回答校验未通过`

同时记录不含个人信息的故障类别、模型别名、耗时区间和是否发生降级，便于运维第一时间发现费用、网络或服务中断。

## 数据流

```text
结构化出生输入
  → 本地历法转换与四柱规则
  → 转换回执与用户确认
  → 规范 ChartFacts
  → 云端 AI 详细分析
  → 本地事实校验
  → 正常回答

云端异常或校验失败
  → 本地完整六段回答
  → 显示明确降级原因
```

## 验收与测试

### 排盘输入

- 农历 1999-07-01 巳时得到公历 1999-08-11 10:00。
- 四柱固定为己卯、壬申、乙未、辛巳。
- 如果同一数字日期选择公历，页面必须明确显示它是公历输入，不能与农历混淆。
- 闰月、非法农历日期、时辰不详和子时前后半段均有边界测试。
- 预览指纹与正式命盘指纹一致。

### 云端回答

- 使用去身份化完整事实和具体问题生成六段回答。
- 连续追问能引用近期真实语境。
- 云端不得改变本地四柱、强弱、格局和喜忌。
- 一次纠正重试后仍不合格时进入本地完整降级。

### 降级回答

- 无 API Key 时返回本地六段回答并显示未配置提示。
- 模拟余额不足时返回本地六段回答并显示额度提示。
- 模拟网络错误、超时和服务异常时显示对应提示。
- 模拟无效结构化响应和事实冲突时进入校验失败降级。
- 日志不包含问题原文、出生资料、API Key 或完整回答。

### 真实命例

- 新增 1999 命例。
- 保留原有 U01–U05 五例。
- 六例分别验证输入回执、正式四柱、云端上下文、云端回答结构、本地降级结构和隐私边界。

## 完成标准

- 客户能明确区分公历和农历输入。
- 农历输入不再使用公历样式日期选择器。
- 正式排盘前能看到原始输入、转换公历、四柱和计算依据。
- 云端正常时由云端负责完整分析和连续问答。
- 云端不可用时仍有基于本地规则的完整六段回答。
- 页面准确显示降级原因，不把所有故障误报为余额不足。
- 四柱与结构事实完全一致，核心判断一致；语言不要求逐字相同。
- 新增 1999 命例和原有五例全部通过。
