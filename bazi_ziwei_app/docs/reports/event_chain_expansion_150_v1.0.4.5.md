## 质量校验机制是否支撑 300+

当前质量校验机制已经可以支撑继续扩展到 300+，原因是它已经具备以下门禁：

- 检查每个证据链事件必须有传统依据、结构依据、宫位依据、现代映射、置信度、反向条件、用户可读依据和子类型规则。
- 检查 `trigger_rules` 至少有 3 条有效触发依据，不能只停留在分类级条件。
- 检查 `source_ids`，没有来源依据的事件不能进入高置信度 Top 事件。
- 检查 `required_evidence_count >= 2`，避免单一符号直接断现实事件。
- 检查相似度，能持续暴露模板化和可合并事件。
- 检查用户可读解释，避免全部是专业术语。

但它不是自动保证准确性的万能机制。扩到 300+ 时仍必须遵守：

1. 每批只扩 30-60 个，不一次性全铺开。
2. 每批先跑 `tools/validate_event_chain_quality.py`。
3. 每批新增专门测试，锁定目标类别和事件数量。
4. 每批检查高相似度列表，把相似事件拆触发条件或合并。
5. 继续人工看 8501 页面里的年度流月输出，确认用户能看懂。
